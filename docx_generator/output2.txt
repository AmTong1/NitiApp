  [Heading 5] Docker [5]เป็นแพลตฟอร์มที่ใช้เทคโนโลยีการจำลองสภาพแวดล้อมในรูปแบบ Container เพื่อทำการบรรจุแอปพลิเคชันและส่วนประกอบที่จำเป็นทั้งหมด (Dependencies) ให้สามารถทำงานร่วมกันได้อย่างเป็นเอกเทศ ในโครงงาน NitiSmart คณะผู้จัดทำได้นำ Docker มาใช้ในการจัดการระบบ Backend และ Database เพื่อแก้ปัญหาความแตกต่างของสภาพแวดล้อมระหว่างเครื่องคอมพิวเตอร์ของผู้พัฒนาและเซิร์ฟเวอร์จริง (Environment Consistency) ช่วยให้การติดตั้งและทดสอบระบบเป็นไปได้อย่างรวดเร็วและแม่นยำ อีกทั้งยังช่วยในการจัดสรรทรัพยากรของระบบให้มีประสิทธิภาพสูงสุด ทำให้การขยายตัวของระบบในอนาคตเพื่อรองรับจำนวนผู้ใช้งานที่เพิ่มขึ้นสามารถทำได้ง่ายและมีความเสถียร

  [Heading 1] บทที่ 5
  [Heading 2] 5.1 สรุปผลการดำเนินงาน (Conclusion)
  [Heading 3] 5.1.1. ระบบจัดการข้อมูลลูกบ้านและผู้ใช้งาน: สามารถบันทึก แก้ไข และแบ่งสิทธิ์การใช้งานระหว่างลูกบ้าน (User) และนิติบุคคล (Admin) ได้อย่างถูกต้องและปลอดภัย
  [Heading 3] 5.1.2 ระบบการเงินและค่าส่วนกลาง: ลูกบ้านสามารถตรวจสอบยอดค้างชำระ และชำระเงินผ่านการสแกน QR Code (PromptPay) ได้ โดยระบบสามารถดึงข้อมูลจากสลิปโอนเงิน (e-Slip) มาตรวจสอบความถูกต้องผ่าน API ของ SlipOK และอัปเดตสถานะการชำระเงินให้อัตโนมัติ ป้องกันปัญหาการส่งสลิปปลอมหรือสลิปซ้ำ
  [Heading 3] 5.1.3. ระบบแจ้งซ่อม: ลูกบ้านสามารถแจ้งปัญหา แจ้งซ่อม พร้อมแนบภาพถ่าย โดยนิติบุคคลสามารถติดตามและอัปเดตสถานะการซ่อมแซมได้อย่างเป็นระบบ
  [Heading 3] 5.1.4. ระบบประกาศข่าวสาร: นิติบุคคลสามารถกระจายข่าวสารและปักหมุดประกาศสำคัญ เพื่อให้ลูกบ้านรับทราบข้อมูลได้อย่างรวดเร็วผ่านแอปพลิเคชัน
  [Heading 3] 5.1.5. ระบบสนทนา (Chat System): ลูกบ้านและนิติบุคคลสามารถติดต่อสื่อสารกันได้แบบ Real-time รองรับการส่งข้อความและรูปภาพ ช่วยลดช่องว่างในการสื่อสาร
  [Heading 2] อภิปรายผล (Discussion)
  [Heading 3] 5.2.1. ด้านความมั่นคงปลอดภัยของข้อมูล: ได้รับคะแนนประเมินสูงสุด เนื่องจากระบบมีการแยกระดับสิทธิ์ผู้ใช้งานชัดเจน และระบบการชำระเงินมีกระบวนการตรวจสอบสลิป (SlipOK Verification) ที่ป้องกันการทุจริตได้อย่างมีประสิทธิภาพ ทำให้ผู้ใช้งานมีความเชื่อมั่นในการทำธุรกรรมทางการเงินผ่านแอปพลิเคชัน
  [Heading 3] 5.2.2. ด้านการออกแบบและความง่ายในการใช้งาน (UX/UI): ผู้ใช้งานพึงพอใจในรูปแบบหน้าจอที่ทันสมัย อ่านง่าย และมีขั้นตอนการใช้งานที่ไม่ซับซ้อน เช่น การจ่ายเงินที่สามารถทำจบได้ในไม่กี่ขั้นตอน
  [Heading 3] 5.2.3. ด้านประสิทธิภาพการทำงาน: ระบบแชท Real-time ที่พัฒนาด้วย Socket.io สามารถส่งข้อความได้รวดเร็วและเสถียร รวมถึงการตรวจสอบสลิปอัตโนมัติที่ทำงานได้แม่นยำ ช่วยลดภาระของนิติบุคคลในการมานั่งตรวจสอบสลิปทีละใบได้อย่างมาก
  [Heading 2] 5.3 ปัญหาและอุปสรรค (Problems and Obstacles)
  [Heading 3] 5.3.1. การเชื่อมต่อกับ API ภายนอก: ในระยะแรกของการพัฒนา การเชื่อมต่อกับ API ของ SlipOK เพื่อตรวจสอบสลิปโอนเงินมีปัญหาเรื่องรูปแบบข้อมูล (JSON Format) ทำให้ต้องใช้เวลาศึกษาคู่มือและปรับแก้โค้ดเพื่อดึงข้อมูลธนาคารและจำนวนเงินมาตรวจสอบให้ถูกต้อง
  [Heading 3] 5.3.2. การจัดการสถานะแบบ Real-time: การพัฒนาระบบแชทและระบบอัปเดตสถานะการแจ้งซ่อมแบบทันที (Real-time) ต้องใช้ความระมัดระวังในการจัดการเซิร์ฟเวอร์ Socket.io เพื่อไม่ให้แอปพลิเคชันเกิดความหน่วงเมื่อมีผู้ใช้งานพร้อมกันหลายคน
  [Heading 3] 5.3.3. ความหลากหลายของหน้าจอสมาร์ทโฟน: การออกแบบ UI ให้รองรับหน้าจอสมาร์ทโฟนที่มีขนาดและสัดส่วนแตกต่างกัน (Responsive Design) บน React Native ต้องใช้เวลาปรับแต่งเพื่อให้องค์ประกอบต่างๆ แสดงผลได้สวยงามบนทุกอุปกรณ์
  [Heading 2] 5.4 ข้อเสนอแนะเพื่อการพัฒนาต่อยอด (Recommendations for Future Work)
  [Heading 3] 5.4.1. ระบบแจ้งเตือนผ่าน Push Notification: ควรเพิ่มระบบ Push Notification (เช่น ใช้ Firebase Cloud Messaging) เพื่อแจ้งเตือนเมื่อมีข้อความแชทใหม่ มีประกาศด่วน หรือใกล้ถึงกำหนดชำระค่าส่วนกลาง แม้ไม่ได้เปิดแอปพลิเคชันค้างไว้
  [Heading 3] 5.4.2. ระบบสแกนป้ายทะเบียนรถหรือบัตรเข้าออก (Access Control): พัฒนาระบบเชื่อมต่อกับกล้องวงจรปิดหรือไม้กั้นหน้าหมู่บ้าน เพื่ออำนวยความสะดวกในการเข้า-ออกของลูกบ้านและผู้มาติดต่อ (Visitor Management)
  [Heading 3] 5.4.3. Dashboard และ Export ข้อมูล: เพิ่มหน้า Dashboard สำหรับนิติบุคคลในการดูสถิติรายรับ-รายจ่ายของหมู่บ้านในรูปแบบกราฟ และสามารถ Export ข้อมูลรายงานทางการเงินออกมาเป็นไฟล์ Excel หรือ PDF เพื่อนำไปทำบัญชีสรุปยอดประจำปีได้ง่ายขึ้น
